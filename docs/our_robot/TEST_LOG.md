# 주차로봇 벤치 시험 기록

최종 정리: 2026-09-04

이 문서는 날짜별 실측값과 문제 해결 과정을 보관하는 참고 기록이다. 최종 핀·전압·안전 한계는 `ELECTRICAL_WIRING.md`, 시스템 설계는 `SYSTEM_HANDOFF.md`를 우선한다.

최신 증거를 먼저 보려면 [2026-09-02 시연 검토](../FINAL_VALIDATION_2026-09-04.md)를
본다. 아래 과거 기록의 미완료·NO-GO 표현은 당시 시험 대상 버전에 대한 판단이다.

## 2026-07-29

- XL4015 #1을 5.1V로 설정해 Raspberry Pi 4를 구동하면서 STM32 USB 통신과 통합 제어가 동작함을 확인했다.
- HC-SR04 #1·#2가 타임아웃 없이 각각 57mm, 79mm를 반환했다. 기준 물체까지의 실제 거리를 함께 측정하지 않았으므로 정확도 보정값으로 사용하지 않는다.

## 2026-08-03

- MDD10A #1의 M1/M2 모터 출력 묶음이 교차되면 제어 채널과 엔코더 피드백이 바뀌어 PID가 포화되는 현상을 확인했다.
- 최종 대응은 MDD10A #1 M1=FL, M2=FR로 정리했다.
- 한 채널이 DIR 한쪽에서 정지하고 반대쪽에서 과속할 때 PWM/DIR 입력선 교차를 먼저 확인해야 한다.

## 모터·엔코더 벤치 시험

- 엔코더 A/B는 풀업 없이 0V에 머물렀고 STM32 입력에 `GPIO_PULLUP`을 적용한 뒤 정상 카운트됐다.
- 기준 모터 출력축을 5회전시켜 총 25,908카운트, 1회전당 약 5,182카운트를 확인했다. STM32 4체배 값이며 모터축 PPR은 아니다.
- 같은 PWM·1.5초 조건의 양방향 카운트는 약 1,469~1,515였고 방향에 따라 부호가 반대였다.
- 4륜 PI 제어의 무부하 목표는 약 12RPM이었다. 정상상태에서 주로 11.1~12.0RPM, 보정 PWM 약 186~216을 확인했다.
- 목표 속도는 50ms마다 1RPM씩 변경해 0→12RPM에 약 0.6초가 걸렸다. 정지 명령과 250ms 통신 단절은 가속·감속 램프 없이 즉시 PWM 0을 적용했다.
- 위 값은 벤치 조건 기록이며 최종 바퀴·하중 상태의 모터별 튜닝값으로 확정하지 않는다.

## 로봇별 서보 시험

- `robot-1` 무마커 프로파일은 시작 400/2600µs, 닫힘 한계 1600/1400µs에서 추가 닫힘 명령에도 멈췄고 다시 400/2600µs로 복귀했다.
- 초기 단계 시험에서 `robot-1`에 닫기 명령 1회를 주면 450/2550µs, 열기 명령 1회를 주면 400/2600µs로 복귀했다.
- `robot-2` ArUco 프로파일은 시작 2600/400µs, 닫힘 한계 1550/1450µs에서 추가 닫힘 명령에도 멈췄고 1500µs에 도달하거나 서로 교차하지 않았다.
- 두 프로파일 모두 최종 차량 하중과 동시 서보 동작에서 6.0V 전압강하·발열을 다시 확인해야 한다.

## 2026-08-20 Front(robot-2) ROS·STM32 실차 통합

- 손으로 네 바퀴를 하나씩 돌리고 단일 바퀴 `±120 PWM`을 인가해 엔코더와 모터 채널을 분리 진단했다.
- 뒤쪽 폐루프 실패의 원인은 RL/RR의 PWM 순서가 `TIM1 CH4/CH3`인데 DIR 별칭이 `MOTOR3/MOTOR4`로 반대였던 논리 채널 불일치였다. 펌웨어에서 RL=`CH4+MOTOR4`, RR=`CH3+MOTOR3`으로 맞췄고 물리 배선은 변경하지 않았다.
- 최종 Front 펌웨어 SHA256은 `8E1FE87275733603CF9FF0B9E34F04D89479CD8349C388DF8FDA28A1921E91D0`이다.
- 잭업 폐루프 직진 5초, 회전 12초, 횡이동 8초에서 네 바퀴가 목표 `11.3~12.0rpm`, PWM 약 `±199~212`로 안정했고 이전의 PWM 350 포화가 사라졌다.
- 무하중 바닥에서 제한 속도 주행과 입력 단절 후 정지를 확인했다. Rear(`robot-1`) 배포와 차량 하중 시험은 남아 있다.

## 2026-08-22 Front(robot-2) Ramp 15 재검증

- PI 게인·피드포워드·PWM 상한은 유지하고 목표속도 램프만 50ms당 1.0RPM(Ramp 10)에서 1.5RPM(Ramp 15)로 높였다.
- Raspberry Pi에서 ST-LINK로 STM32 펌웨어를 직접 기록하고 flash readback 일치와 정지 UART 시험을 확인했다.
- 1.5초 전진 시험은 약 0.51초에 목표 구간에 진입했고 이후 네 바퀴가 11.1~11.8RPM, PWM 약 202~211로 안정했다. Ramp 10 기준의 약 0.64초보다 빨랐으며 포화·발산·오버슈트가 없었다.
- 회전은 FL/RL 양수·FR/RR 음수, 횡이동은 FL/RR 양수·FR/RL 음수의 정상 부호로 11~12RPM에 안정했고 제한 시간 뒤 모두 자동 정지했다.
- 무하중 저속 운용에서는 Ramp 15를 유지하고 PI 게인은 더 변경하지 않기로 했다. Rear(`robot-1`)은 교체 STM32 Nucleo가 아직 도착하지 않아 이번 실차 검증 대상에서 제외했다.

## 2026-08-25 Rear(robot-1) 교체 Nucleo와 엔코더 재진단

- 교체 Nucleo를 장착하고 Rear 통합 후보 32,812바이트(SHA256 `7C4EF22511EEFEAE43E93514BC5AFAEC4E5D99DB5DD3B1D5D064208EA25107A3`)를 Raspberry Pi의 ST-LINK에서 기록했다. 같은 크기의 flash readback SHA256이 일치했다.
- 정지 `X` 전용 UART 시험에서 RPM·PWM은 모두 0, Rear 서보 시작값은 400/2600µs였다. 서보 동작 명령은 보내지 않았다.
- 정상 FL 엔코더를 RL 입력에 연결하면 RL 카운트가 정상으로 변해 새 보드의 RL 입력 경로를 확인했다. RL은 기존 5V 공급 경로를 수정한 뒤 손회전 검출이 복구됐다.
- 정상 RL 엔코더를 RR 입력에 연결하면 RR 카운트가 정상으로 변했지만 실제 RR 엔코더를 RL 입력에 연결하면 0~1만 나타났다. RR 어셈블리는 다른 로봇의 정상 입력에서 검출된 이력이 있으므로 `robot-1` RR 보라/파랑 하네스·커넥터를 우선 수리한다.
- RR 수리와 A/B 진단배선 원복 전에는 ROS·PID·바닥 주행을 진행하지 않는다.
- 실물 방향 확인에 따라 `robot-1` 역할별 축 방향 보정을 수정했다.

## 2026-08-26 협동 시험 전 서보 마지막값 수정

- 두 로봇의 그리퍼가 실제로 최대 벌림 상태인 가운데 협동 launch를 처음 실행했을
  때 `robot-2` RPi의 저장값이 거의 닫힘 위치인 `1500/1450µs`로 남아 있어 사용자가
  물리 비상정지로 전원을 차단하고 다시 인가했다. 주행은 시작하지 않았다.
- `robot-1` 최대 벌림 저장값은 `400/2600µs`로 이미 정확했다. `robot-2`의 기존
  파일은 `robot-2_servo.before_open_fix_20260826.json`으로 백업하고 최대 벌림값
  `2600/400µs`로 원자 저장했다.
- 재기동한 Front bridge가 `robot-2` 복원값 `(2600, 400)`을 요청한 것을 확인했다.
  이후 양쪽 `hardware_ready=true`, 네 바퀴 RPM/PWM 0, ID0 거리 약 0.258m인
  `IDLE` 상태에서 대시보드와 카메라 프리뷰가 정상 동작했다.

## 2026-08-26 3cm 협동 주행 미확정 문제

- 바닥에서 실시한 3cm 자동 시험 두 번 모두 차량의 외관상 움직임은 사용자가
  정상으로 판단했지만, 시험 노드는 오도메트리에서 명령과 반대 부호의 이동을
  검출해 `명령 반대 방향 이동 감지`로 정지했다. 따라서 이 시험을 최종 통과로
  판정하지 않으며, 다음 주행 전에 로봇별 전진 명령과 오도메트리 부호를 따로
  대조해야 한다.
- 같은 운용 중 Front(`robot-2`) bridge에 오래된 속도 명령 거부 기록이 반복됐다.
  두 Raspberry Pi의 시계 동기화와 송신 시각을 확인하기 전에는 분산 명령의 전달이
  항상 정상이라고 간주하지 않는다.

## 2026-08-27 ID0 중심거리 offset 확정

- 운용자가 정상 정렬 상태의 Rear 카메라→Front ID0 raw 거리를 약 `0.215m`로
  확인했다. 별도 IDLE 배치에서 기록된 `0.258m`는 같은 중심 간격의 값이 아니므로
  offset 계산에 섞지 않는다.
- 실측 로봇 중심 간 거리 `0.785m`에서 raw `0.215m`를 빼
  `aruco_distance_offset_m=0.570m`로 정했다.
- 이 값은 카메라·마커 장착 위치 보정이며 로봇 외곽 길이 `0.565m`와 다른 상수다.
  다음 정면 배치 때 여러 프레임의 중앙값이 21.5cm 부근인지 재확인한다.

## 2026-08-28~29 강체 쌍과 pregrip 통합

- pair heading hold, 연속 gap correction, ArUco pose jump plausibility와
  3-sample 복구를 통합했다.
- 차량 하부 진입 뒤 grip 직전에 멈추는 `stop_after_align`을 추가했다. 양쪽
  `aligned_hold=true`와 0속도를 유지하고 LIFT ready/commit을 차단한다.
- 교체된 천장 CCTV asset을 640x360 기준으로 대조해 직접 launch 기본값과 현장
  광축 지상점 우선순위를 수정했고, 5008 듀얼 CCTV 관제탑을 기본 기동하도록 했다.
- clean ROS 2 Humble build와 package 자동 회귀를 확인했다. 자동 검증 결과는
  실기 통과를 대신하지 않는다.
- 최신 통합본은 동일 SHA 배포와 현장 preflight 전까지 차량 하부 자동 진입을
  NO-GO로 유지한다.
